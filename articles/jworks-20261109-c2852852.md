Claude Codeのクラウドセッションについて公式ドキュメントを確認すると、「利用できるプランか」と「どの方法でGitHubにつなぐか」は、使い始める前に分けて確認したほうがよい点でした。GitHubに接続できれば機能をすべて使える、というわけではありません。特に、`/web-setup`で接続した場合も、プロジェクトのスレッドにはClaude GitHub Appが必要です。

設定を試してから条件に合わないと分かると、どこを見直せばよいか判断しにくくなります。今回は、公式ドキュメントで確認できた利用条件と接続方式を整理します。実際に環境を構築して動作を検証した話ではなく、ドキュメントに記載された範囲を読むときの確認ポイントです。

## まずプランと組織の設定を見る

公式ドキュメントによると、Claude CodeのクラウドセッションはPro、Max、Teamプランで利用できます。一方、Zero Data Retention（データを保持しない契約）やHIPAA設定を使っている組織、顧客管理の暗号鍵（CMEK）を使っている組織では、クラウドセッションの機能を使えません。

ここでは、プランだけを見て利用可否を判断しないことが大切です。対象のプランであっても、組織の設定によっては使えない場合があります。個人で利用しているときと、組織の管理下で利用しているときでは、確認すべき条件が異なることがあります。

利用を始める前に、まず自分のプランを確認し、組織で使っている設定が制限に該当しないかを確かめる。この順番なら、GitHubの接続方法を選ぶ前に、そもそも機能を利用できる条件なのかを切り分けられます。

## GitHubの接続方法は、必要な機能と合わせて選ぶ

ドキュメントでは、ブラウザーからClaude GitHub Appを使って接続する方法と、端末で`/web-setup`を実行して、手元の`gh`のトークンを送る方法が案内されています。どちらもGitHubとの接続に関係しますが、同じ機能要件を満たすとは限りません。

特に見落としやすいのが、`/web-setup`で接続した場合の制約です。この方法で接続しても、プロジェクトのスレッドを使うにはClaude GitHub Appが必要です。つまり、接続自体ができたことと、使いたい機能の前提を満たしたことは別に確認する必要があります。

「まず接続できる方法を選ぶ」だけでは、後から使いたい機能の条件に気づくことがあります。先にプロジェクトのスレッドが必要かを考え、その要件に合う接続方法かを確かめておけば、接続後の見直しを減らせそうです。

## 接続できたことを、利用条件の確認と混同しない

今回確認した条件は、大きく二つに分けられます。一つはプランと組織設定による利用可否、もう一つはGitHubの接続方式と必要な機能の対応です。前者はクラウドセッションを利用できるか、後者は選んだ接続方法で目的の機能を使えるかに関わります。

この二つをまとめて「GitHubにつながったから準備完了」と判断すると、プランや組織設定の制限、プロジェクトのスレッドに必要な接続方式を見落とす可能性があります。確認する場所が異なるため、利用可否と接続要件を分けて見るほうが、つまずいたときの原因も整理しやすくなります。

## 始める前の確認を二段階にする

Claude Codeのクラウドセッションを使う前には、まずプランと組織設定が利用条件に合うかを確認し、次にGitHubの接続方式が使いたい機能の要件に合うかを確認します。`/web-setup`で接続できることだけを、プロジェクトのスレッドも利用できる根拠にはできません。

今回分かったのは、クラウドセッションの準備では「利用できるか」と「目的の機能に必要な接続か」を別々に確かめる必要があるということです。動かし始める前にこの二点を見ておけば、接続の成功だけで判断してしまうのを避けられます。
